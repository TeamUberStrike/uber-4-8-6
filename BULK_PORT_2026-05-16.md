> **OUTCOME: REVERTED at 2026-05-16 23:30.** Bulk port introduced unrecoverable
> shader compile errors. Even after extensive Unity 4.6 compat patches, Unity's
> shader compile pipeline kept emitting the same errors at the same line numbers
> across multiple Library refreshes — pink (magenta fallback) UI everywhere.
> Restored from `.bak_bulk-shader-material-port_2026-05-16_230252/`.
>
> **Lesson:** Bulk-copying U6 fork's `Assets/Shader/` is too aggressive. Even with
> the compat sweep covering UnityObjectToClipPos, UNITY_VERTEX_INPUT_INSTANCE_ID,
> UNITY_PI, UNITY_DECLARE_DEPTH_TEXTURE, UNITY_INITIALIZE_OUTPUT etc., enough
> Unity-5+ constructs slipped through to leave the pipeline stuck. For
> stretched-mesh fixes, do per-material surgical copies instead: identify the
> ONE shader a broken material needs (e.g. "Reflective/Diffuse" for Building_A
> glass towers), copy just that .shader + .meta, compat-scan it alone, rebind
> the affected materials, test, repeat.


## Why
Diagnostic on 2026-05-16 evening found 346 of 539 materials in this project bound
to **wrong shaders** vs the working `ForgeRipper/data/UberStrike_Unity6` fork —
the result of AssetRipper remapping everything to Unity's built-in Standard
shader during the Unity 6 → Unity 4.6.5 round-trip. Symptom: 3D meshes appear
"stretched" (vine billboards, glass towers, skyboxes), particles render wrong,
shop UI text was ghosted, etc.

Per-symptom whack-a-mole was not converging. The Unity 6 fork already documented
fixes for all of this (see `vault/sessions/2026-04-14`, `2026-04-17`). Strategy:
bulk-copy the U6 fork's `Assets/Shader/` + `Assets/Material/` into this project
in one shot — same shader GUIDs, same material bindings — then patch Unity-5+
shader syntax for Unity 4.6 compat where it breaks.

## What got changed
- `Assets/Shader/` — replaced entirely with `ForgeRipper/data/UberStrike_Unity6/Assets/Shader/`
- `Assets/Material/` — replaced entirely with `ForgeRipper/data/UberStrike_Unity6/Assets/Material/`
- Unity-5+ shader macros patched to Unity-4.6 equivalents (`UnityObjectToClipPos` → `mul(UNITY_MATRIX_MVP, v.vertex)`, etc.)

## How to verify after Unity reimports
1. Close Unity → delete `Library/` → reopen (full reimport ~3 min)
2. Press Play on `GlobalScene.unity`
3. Expected positives:
   - Lobby UI text crisp (no ghost/glow)
   - 3D scene props rendering correctly (Building_A/B vines, props, particles)
   - Skyboxes bright
   - Particles look right (smoke, fire, explosions)
4. Expected negatives:
   - 88 U6 materials that didn't exist in target are now added — harmless extras
   - Some textures may appear pink if U6 .mat references a texture GUID not in our project
   - Any Unity-5+ shader macros not auto-patched will throw shader compile errors → fixable per-file
